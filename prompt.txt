cmx CLI customized package

I want to create a new custom package for managing and bridging every technical realm together into
    one CLI command for me to do everything in the terminal. This should support both Mac and Linux
    based systems, and each feature should require no external dependencies at all; this means any
    dependencies we do use must be imported as files into the repository itself. The cmx CLI package
    should be completely implemented in Rust, using optimized Rust code to make it ultra-low
    latency. Here is a list of features I want:

* A near natural language-style code to LaTeX and natural language proof-prose

We need a new command:
cmx stex new - creates an untitled .stex file, opens it in the cmx editor (see design above), which
    later you have to name yourself to save (kind of like vim)
cmx stex new [filename] - creates a blank filename.stex
cmx stex check [filename.stex] - converts the .stex to a lean file with whatever script you build
    and uses lean to check the proof. Places the lean file in the current repository
cmx stex compile [filename.stex] [--fixed | --natural | —varied | --random (variance flags)] [--open]
    [--pdflatex | --xelatex | --lualatex] - compiles the .stex file into a complete, final .tex
    file, called filename.tex (which is then also compiled into a LaTeX pdf with pdfLaTeX). adding
    the flag --open prompts the default browser to open to view the pdf through the directory path
    in the browser. default is pdflatex compilation. the first time you run this, it generates a
    .tex and a pdf, sharing the exact name as filename.stex, except that it is filename.tex and
    filename.pdf. subsequent runs will just recompile into tex and pdf, not create a new tex or pdf
    (unless the name of tex and pdf is manually changed to something else).

Features:
0- a new file type: .stex (short for steno-text or short-tex), which is compiles the near-natural
    language written in stex DETERMINISTICALLY INTO LaTeX when compiled by cmx — no training of LLM
    models is allowed.
1- Example: let x = 5. Auto recognition of which part of the script is prose (“let”) and which part
    is math ($x=5$); so this becomes Let $x = 5$. There should be a detection of which are variables 
    and which are text based on likelihoods and largely-deterministic simple probabilities
2- let x in integers —> auto converts to: Let $x \in \mathbb{Z}$
3- auto-adding buffer words between abbreviated declarations, etc. Example: let x = 5, y > 4, z in Z
    -> automatically becomes “Let $x = 5$, let $y > 4$, and let $z \in \mathbb{Z}$” in LaTeX; this
    auto addition should have context based on what is
4- exists x in Z such that x^20+30 choose 4 —> auto converts to: $x^{20}+\binom{30}{4}$ for some $x
    \in \mathbb{Z}$
5- define f: N to N via f(x) = 2x^34 + 7 —> auto converts to: Define $f: \mathbb{N} \to \mathbb{N}$
    via $f(x) = 2x^{34}  + 7$.
6- other non built in words are interpreted as natural language and thus are part of the sentences
    as prose.
7- auto checker while cmx stex is run with check, e.g. cmx stex check [file] —> the cmx auto
    converts the proof into lean, and checks that the proof is correct
8- auto-formatter upon compile: reformatting here entails changing up the spacing, paragraphs, etc.
    so that we don’t have cut off text, split paragraphs, or too much blank page (this will need
    extensive casing, so as to differentiate between one page with multiple short sections or one
    long section spanning 2+ pages)
9- auto detection of what common packages are needed in the output .tex file, e.g. amsmath,
    amsfonts, amsthm, amssymb, enumerate, fullpage, changepage, tikz, graphicx, etc.
10- auto detection of sentence boundaries, and autocapitalization and punctuation of sentences.
    Saying “let x = 5, let y = 6, let z = 7” and “let x = 5. let y = 6. let z = 7” should be
    different, and render in the .tex as “Let $x = 5$, let $y = 6$, and let $z = 7$” and “Let $x =
    5$. Let $y = 6$. Let $z = 7$.” respectively
11- an internal library of all 200,000 lean theorems, written in lean, to use for verifying the
    proofs. If a user writes in stex “let x,y in Z, let m,n be moduli, x ==  exists k in integers
    s.t. k == m mod n by the Chinese Remainder Theorem” — it should detect that the CRT was invoked,
    and if cmx stex check is run, then lean should also use the CRT representation in Lean as part
    of its proof verification process. in your library of equivalent words, you should store sets of
    different macros for the same theorem, e.g. {CRT, Chinese Remainder Theorem, etc.} in an
    efficient manner so that equivalent words can be caught on, even though “by the Chinese
    Remainder Theorem” itself is counted as prose.
12- library of thousands of words to math symbols: e.g. empty set is the \varnothing, greek letters
    converting to the latex equivalent, union and intersect, etc.

Anyway, adding flags --fixed | --natural | --varied | --random, which are variance flags, signals to
    the .stex to .tex compiler HOW varied the prose is. Fixed is little no variance in prose, with
    nearly 95% of prose predictable, using very common prose and the same transition, e.g. Let…
    Then, it follows that, this implies… etc. Natural would use a more diverse set of prose options;
    leaning towards a distribution of phrases that make a proof sound naturally. You may need to
    analyze a lot of mathematical proofs you find online to create a frequency table of what
    transitions are most common. Varied would increase the diversity of phrases used, and random
    would be purely random.

Onto the actual syntax/features of stex:
wts: invokes prose for the claim, e.g. wts x = 5 yields prose like "We show that ..."
let: invokes prose equivalent to let, fix, let _ be arbitrary, etc…
assume: invokes prose equivalent to suppose, suppose that, assume, assume that, etc.
afsoc or aftsoc: invokes prose equivalent to “Assume for the sake of contradiction”
contradition: invokes prose equivalent to ""
then/implies: invokes prose equivalent to then, it follows that, this implies (see above for more
    equivalents), or logical implies symbol when used inside $$
and, &&: just a logical and, and the symbol for logical and symbol when used inside $$
or, ||: representing a disjunction in the prose, or logical or symbol when used inside $$
    Note: absolute value, cardinality, and magnitude are represented only when there is at least one
    character between the two pipes ||
not, !: representing the negation of the prose, or logical not symbol when used inside $$. Should be
    able to be used anywhere in a claim: e.g. let not x = 5 or let x not = 5 or let x not equals 5
    or let x neq 5 should result in the same thing: Let $x \neq 5$.
    Note: ! with a number in front of it acts as a factorial, not a not. ! has to be concatenated directly
          in front of an expression, such as !=, !==, !x = 5. By itself or near prose, ! acts as the textual
          exclamation mark!
xor, ^^: representing either-or in the prose, or logical xor symbol when used inside $$
nand, !&&: same idea as above
nor, !||: same idea as above

iff: invokes prose equivalent to if and only if, precisely when, exactly when, etc.; or logical \iff when used inside $$

exists x, P(x): invokes prose equivalent to "There exists $x$ such that $P(x)$." (default) or "We have $P(x)$ for some $x$." or
                plenty of other equivalents, depending on the variation level (the variation flag), or the existential quantifier 
                (backwards E) when used in $$. In the --natural prose variation level, the two mentioned variations hold equal weight.
    equivalent syntax: come up with a list of equivalent stex syntax that works for exists, that is near exhaustive, e.g.
    there exists x, P(x); exists x such that P(x); exists x st P(x); exists x s.t. P(x), ..., and many more.

for every x, P(x): invokes prose equivalent to "For every(default)/all/each $x$, $P(x)$" (default) or "We have $P(x)$ for all $x$."
                  and plenty of equivalents. This also depends on the variation level (if fixed, we always use default.) In the 
                  --natural prose variation level, the two mentioned variations hold equal weight.
    equivalent syntax: come up with a list of equivalent stex syntax that works for "for every", that is near exhaustive, e.g.
    for all x, P(x); for every, x P(x); for each x P(x) (no comma), ..., and many more.

=: yields $=$, ex. x = 5 yields $x = 5$
==: yield $\equiv$, ex. x == 5 mod 6 yields $x=$

{}: should just be used for sets, e.g. $\{\}$

define ... via / := : defines a function, set, relation, etc.. The stex compiler should then keep track of the definition. 

mod n: yields $\pmod{n}$ (detects an \equiv nearby), or $\bmod$
%: yields $\bmod$ or $\%$ if a number preceeds it
    ex. 5% % 6% yields $5\% \bmod{}$

sqrt: yields \sqrt{}
nrt: yields \sqrt[n]{}
    ex. 3rt(5) yields \sqrt[3]{5}
        7rt 6 yields \sqrt[7]{6}

*/dot: yields \cdot
cross: yields \times

/ or over: yields \frac{a}{b}
    Note: parse divides like normal text PEMDAS; a+b/c yields a + \frac{b}{c}, but (a+b)/c yields \frac{a+b}{c}.
    Let parentheses clarify.

+, -, +-, -+, (), [], ><, >=, <=: use as normal arithmetic, grouping, or comparison operations

b/c / because/since/by (either prose or an expression, not a theorem): invokes prose equivalent to because/since/due to/ as a result, etc.
        In --fixed, explicitly use either one of them exactly. In natural, extend to other synonyms like "due to" or 
        "as a result of", etc. This reasoning is prose and is ignored by lean when you run cmx stex check

by (Theorem/Axiom/Lemma/assumption): invokes prose invoking the theorem depending on where it is placed syntactically; i.e.,
    by CRT k == a mod m and k == b mod n
    yields: "By the Chinese Remainder Theorem, $k \equiv a \pmod{m}$ and $k \equiv b \pmod{n}$."

    conversely, k == a mod m and k == b mod n by CRT
    yields: "$k \equiv a \pmod{m}$ and $k \equiv b \pmod{n}$ by the Chinese Remainder Theorem", or "We have ... by the Chinese Remainder Theorem." or something like that
    
    This adds this theorem to be checked by lean when you run cmx stex check. If by is called, IF we can detect a theorem or a theorem abbreviation, 
    then it has the special property of being added to the lean check during proof verification.

by inside $$: can be used to add tags in the \begin{align}, for reasoning
    ex. $
            x^2 = 9 implies x^2 - 9 = 0 by subtraction, implies (x+3)(x-3) = 0 by factoring, implies x = 3 or x - 3 by simplifying
        $
    yields:
        \begin{align}
            x^2 = 9 &\implies x^2 - 9 = 0 \tag*{subtraction}\\
                    &\implies (x + 3)(x - 3) = 0 \tag*{factoring}\\
                    &\implies x = 3 \lor x = -3 \tag*{simplifying}\\
        \end{align}

w/, with: expands to "with" in prose
    ex. let x in integers w/ x > 5, this yields: Let $x \in \mathbb{Z}$ with $x > 5$.

$$: inside an align or a math symbol section (double $$$$) that purely involves logic and mathematical

    a keyword gets wrapped in \text{}. Ex. $exists x such that x = 5y$ necessarily becomes 
    $\exists x, \; x = 5y$ in the resulting .tex
    Note: IF it is a long chain of implies or equals or biimplicationals, prefer \begin{align}; but if it is a short
    chain or just a singular equation, prefer $$expression$$. The criteria is whether it fits cleanly in 1 line to
    prefer one over the other.

thousands of actual words to symbols: empty set; greek letters like alpha, beta, theta, lambda,
